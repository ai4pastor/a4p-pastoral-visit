# A4P Pastoral Visit — 성도·심방 관리 플러그인 기획서

> 옵시디언 볼트 안에서 성도 명부와 심방 기록을 하나의 흐름으로 관리하는 플러그인.
> 대상: 옵시디언 강의를 수료한 중급 수준의 한국 목회자.

---

## 1. 배경과 문제 정의

### 1.1 현재 워크플로우 (수작업 기준)

강의에서 시연한 성도 관리 볼트 구조는 이미 잘 동작한다:

- **성도 노트** (`type: 교인노트`, 파일명 = 성도 이름) — 인적사항·직분·구역·출석·봉사 이력을 프론트매터로 관리
- **심방일지** (`type: 심방일지`, 파일명 `{YYMMDD}_심방일지_{이름}`) — 심방 1건당 노트 1개, 7개 고정 섹션
- **Obsidian Bases** (`성도 관리.base`, `심방 관리.base`) — 명부·출석·봉사·심방 현황 뷰
- **양방향 연결** — 심방일지는 프론트매터 `성도` 필드로 성도 노트를 가리키고, 성도 노트는 `## 📝 심방 기록` 링크 목록과 `## 📌 중요 심방 내용 (임베드)` 섹션 임베드로 일지를 되가리킴

문제는 이 구조를 **손으로 유지하는 비용**이다. 심방 1건을 기록하려면:

1. 심방일지 폴더에 새 파일 생성
2. 파일명 규칙(`260308_심방일지_홍길동`) 정확히 타이핑
3. 템플릿 붙여넣기, 프론트매터 5개 필드 입력
4. `📋 기본정보` 섹션에 성도 노트의 프론트매터 내용을 **옮겨 적기**
5. 본문(대화내용·기도제목·후속조치 등) 작성
6. 성도 노트 열기
7. `## 📝 심방 기록`에 wikilink + 한 줄 요약 추가
8. `## 📌 중요 심방 내용 (임베드)`에 `### 날짜 유형` 헤딩 + 임베드 3줄 문법 타이핑
9. 프론트매터 `심방상태`를 `필요 → 완료`로 수정
10. 후속조치 체크박스는… 어느 일지에 있었는지 기억에 의존

**약 10단계, 5분 이상.** 그리고 매 단계가 실수 지점이다.

### 1.2 수작업 고통점 5가지 (플러그인이 풀 문제)

| # | 고통점 | 실수했을 때 결과 |
|---|--------|------------------|
| 1 | 파일명 규칙 준수 (`{YYMMDD}_심방일지_{이름}`) | 자동화·정렬·검색 전부 깨짐 |
| 2 | 성도 노트에 링크·요약·임베드 수동 추가 | 임베드 문법 오타 → 빈 임베드, 누락 → 이력 유실 |
| 3 | 프론트매터 `심방상태` 수동 갱신 | Bases 심방 관리 뷰가 현실과 어긋남 |
| 4 | 후속조치 체크박스 추적 | "수술 전에 다시 찾아뵙기로 한 약속"이 묻힘 |
| 5 | `📋 기본정보`를 성도 노트에서 옮겨 적기 | 단순 반복 노동 + 정보 불일치 |

### 1.3 대상 페르소나

- **중급 목회자** — 옵시디언 강의 수료 수준. 프론트매터·wikilink·태그·Bases를 이해하고 쓸 수 있음.
- 다만 섹션 임베드 문법(`![[파일#헤딩]]`), 파일명 규칙, 상태 필드 일관성 유지 같은 **구조 관리**는 실수하기 쉽고 귀찮아함.
- 성도 수 50~300명 규모의 교회를 섬기며, 주중 심방 1~5건.
- 데이터에 대한 태도: 성도 정보는 민감하다는 감각이 있으나, 기술적 보호 수단은 잘 모름.

## 2. 컨셉과 설계 철학

### 2.1 컨셉 한 줄

> **"타이핑은 목양 내용에만, 구조는 플러그인이."**

목회자가 손으로 쓰는 것은 대화내용·기도제목·후속조치 같은 **목양의 알맹이**뿐이어야 한다. 파일명, 프론트매터, 링크, 임베드, 상태 갱신 — 구조에 해당하는 모든 것은 플러그인이 만든다.

### 2.2 설계 원칙 (a4p 플러그인군 공통 규율 승계)

1. **비파괴 (Non-destructive)** — 파일 삭제 기능 없음. 기존 노트의 기존 줄은 절대 수정·삭제하지 않고 **append만** 한다. 예외는 사용자가 명시적으로 클릭한 단일 변경(체크박스 토글, 심방상태 갱신)뿐.
2. **미리보기 후 승인** — 노트를 변경하는 작업은 반드시 변경 내용을 미리 보여주고 사용자가 승인한 뒤 실행한다 (dry-run 원칙).
3. **전부 한국어 UI** — 커맨드 이름, 모달, 설정, Notice 모두 한국어.
4. **노트가 단일 진실** — 플러그인 전용 DB를 만들지 않는다. 모든 데이터는 마크다운 노트와 프론트매터에 있고, 플러그인은 그것을 읽고 쓰는 도우미일 뿐. 플러그인을 지워도 볼트는 온전하다.
5. **기존 자산과 역할 분담** — 통계·분석 뷰는 이미 `성도 관리.base`(뷰 9개)가 잘한다. 플러그인 패널은 **"지금 할 일"**(actionable)에만 집중하고, 분석은 Bases로 위임한다.
6. **분류 체계 오염 방지** — 직분·구역·신급 등의 드롭다운 선택지는 기존 성도 노트들을 스캔해 **실제 사용 중인 값**에서 수집한다. 플러그인이 임의의 새 값을 만들어내지 않는다.

## 3. 데이터 모델 (표준 스키마)

기존 볼트 샘플(`400. Education & Ministry/460. 성도/`)의 구조를 그대로 표준으로 삼는다. 플러그인이 새 형식을 강요하지 않고, 강의에서 이미 가르친 구조를 자동화한다.

### 3.1 성도 노트 (`type: 교인노트`)

- **위치**: 설정된 성도 폴더 (기본값 `400. Education & Ministry/460. 성도`)
- **파일명**: 성도 이름 (동명이인은 `이름(구역)` 형태)

| 필드 | 타입 | 예시 | 비고 |
|------|------|------|------|
| `type` | 고정값 | `교인노트` | 노트 유형 식별자 |
| `이름` | 텍스트 | `홍길동` | Bases 필터 조건 |
| `성별` | 선택 | `남` / `여` | |
| `생년월일` | 날짜 | `1977-12-06` | 나이·생일 계산 |
| `연락처` | 텍스트 | `010-****-****` | 마스킹 대상 |
| `직분` | 선택 | `성도`·`집사`·`권사`·`장로`·`전도사`·`청년` 등 | 기존 값 스캔 |
| `구역` | 선택 | `4구역` | Bases groupBy 기준 |
| `등록일` | 날짜 | `2022-07-03` | 등록기간·새신자 판별 |
| `세례여부` | 선택 | `세례`·`유아세례`·`입교` | |
| `결혼여부` | 선택 | `기혼`·`미혼` | |
| `신급` | 선택 | `새신자`·`학습교인`·`세례교인`·`등록교인` | |
| `가족수` | 숫자 | `4` | |
| `가족관계` | wikilink | `"[[박순옥]] (배우자)"` | 가족 성도 연결 |
| `심방상태` | 선택 | `필요`·`완료`·`불필요` | **플러그인이 갱신** |
| `{연도}년 봉사` | 텍스트 | `2026년 봉사: 성가대` | 연도별 개별 키 |
| `새벽기도`·`수요기도회`·`금요기도회`·`주일예배` | 선택 | `자주참석`·`가끔참석`·`참석하지않음` | 출석점수 계산 |

**본문 골격** (플러그인이 생성·유지하는 두 섹션):

```markdown
# 홍길동

## 📝 심방 기록
- [[260308_심방일지_홍길동]] — 정기심방 (2026-03-08), 시니어 소그룹 후기, 박순옥 권사 무릎 수술

## 📌 중요 심방 내용 (임베드)
### 2026-03-08 정기심방
![[260308_심방일지_홍길동#📝 대화내용]]
![[260308_심방일지_홍길동#🙏 기도제목]]
![[260308_심방일지_홍길동#💡 후속조치]]
```

### 3.2 심방일지 (`type: 심방일지`)

- **위치**: 성도 폴더 하위 `심방일지/`
- **파일명**: `{YYMMDD}_심방일지_{성도이름}` — 플러그인이 생성하므로 규칙 위반 불가능

| 필드 | 타입 | 예시 | 비고 |
|------|------|------|------|
| `type` | 고정값 | `심방일지` | |
| `성도` | wikilink | `"[[홍길동]]"` | 성도 노트 역참조 |
| `날짜` | 날짜 | `2026-03-08` | |
| `장소` | 텍스트 | `자택 거실` | 최근 사용값 서제스트 |
| `동행` | 텍스트 | `이재훈 장로` | 선택 |
| `심방유형` | 선택 | `정기심방`·`특별심방`·`위로심방` | |
| `반영` | 불리언/날짜 | `true` | **플러그인 전용** — 성도 노트 반영 여부 (멱등성 키) |

**본문 7개 고정 섹션**:

```markdown
# 심방기록 — 2026-03-08 홍길동

## 📋 기본정보      ← 성도 노트 프론트매터에서 자동 채움
## 📍 심방정보      ← 작성 모달 입력값으로 자동 채움
## 📝 대화내용      ← 목회자 직접 작성 (커서 시작 위치)
## 🙏 기도제목
## ⛪ 교회 관련
## 🔍 관찰 및 평가
## 💡 후속조치      ← - [ ] 체크박스 액션 아이템
```

### 3.3 섹션 앵커 규약 (⚠️ 임베드가 깨지지 않는 조건)

성도 노트의 임베드는 심방일지의 **헤딩 텍스트와 정확히 일치**해야 동작한다:

- `![[일지#📝 대화내용]]` ↔ 일지의 `## 📝 대화내용`
- `![[일지#🙏 기도제목]]` ↔ 일지의 `## 🙏 기도제목`
- `![[일지#💡 후속조치]]` ↔ 일지의 `## 💡 후속조치`

**이모지 포함 헤딩 전체가 앵커다.** 사용자가 일지 헤딩을 수정하면 성도 노트의 임베드가 깨진다. 플러그인은:
1. 일지 생성 시 헤딩을 상수로 박아 오타 원천 차단
2. (v0.2+) 일지 헤딩 변경 감지 시 경고 Notice

## 4. 핵심 기능 명세 — 워크플로우 5종

### 4.1 (a) 새 성도 등록 — 모달, 클릭 2회로 시작

- **진입점**: 리본 아이콘 → 패널 `+ 새 성도` 버튼 / 커맨드 팔레트 `성도: 새 성도 등록`
- **UI**: 단일 모달, 2단 구성
  - **필수(상단)**: 이름, 성별(라디오), 생년월일, 연락처, 구역(기존 값 드롭다운+직접입력), 직분(드롭다운)
  - **선택(하단, `▸ 상세 정보` 접힘)**: 등록일(기본 오늘), 세례여부, 결혼여부, 신급, 가족수, 가족관계(성도 자동완성+관계 라벨), 출석 4종
- **동작**: 저장 → 성도 폴더에 `{이름}.md` 생성 (프론트매터 전체 + 본문 골격 2섹션), `심방상태: 필요` 초기화(신규 등록 = 초기 심방 대상), 생성 후 노트 열기
- **엣지 케이스**: 동명이인 — 파일 존재 감지 시 `홍길동(4구역)` 형태 파일명 제안. **기존 파일 덮어쓰기 절대 금지.**
- **입력 비용**: 필수 6필드, 클릭 2회 + 저장 1회

### 4.2 (b) 심방 전 준비: 성도 브리핑 — 클릭 1회, 입력 0회 (v0.2)

- **진입점**: ① 성도 노트에서 커맨드 `성도: 심방 브리핑` ② 패널 성도 목록의 `📄` 아이콘 ③ 파일 컨텍스트 메뉴
- **UI**: 모달이 아닌 **사이드 패널 브리핑 탭** — 심방 중 일지 초안과 나란히 띄울 수 있어야 하므로
- **내용 (우선순위 순)**:
  1. 헤더: 이름 · 직분 · 구역 · 나이 · 심방상태 배지
  2. ⏱ **마지막 심방**: 날짜 + "N개월 전" + 유형 (없으면 "심방 기록 없음" 강조)
  3. 💡 **미완 후속조치**: 이 성도의 모든 일지에서 미체크 항목 수집 — 심방 가서 가장 먼저 챙길 것
  4. 🙏 **최근 기도제목**: 최근 일지 1~2건의 기도제목 원문
  5. 👨‍👩‍👧 **가족**: 가족관계 링크 + 각자의 심방상태·최근 심방일
  6. 📝 심방 이력 타임라인 (클릭 시 일지 열기)
  7. 참고: 생일 임박, 등록기간, 올해 봉사, 출석 패턴
- **하단 버튼**: `이 성도 심방일지 작성 →` (워크플로우 c 직결)

### 4.3 (c) 심방 후 일지 작성 — 하이브리드: 모달은 메타만, 본문은 에디터

**설계 결정**: 모달 100%도, 수동 템플릿 100%도 아닌 하이브리드.
- 긴 서술(대화내용·관찰평가)을 모달 textarea에 쓰게 하면 옵시디언 에디터의 장점(링크 자동완성·자유 편집)을 버리는 것
- 반면 파일명 규칙과 프론트매터는 수작업 실수의 주범 → 모달이 강제

- **진입점**: ① 브리핑 탭 버튼 ② 커맨드 `성도: 심방일지 작성` ③ 성도 노트에서 실행 시 성도 프리필
- **모달 입력 5개** (성도 노트에서 진입 시 실질 2~3개): 성도(자동완성·프리필) / 날짜(기본 오늘) / 장소(최근 사용값 서제스트) / 동행(선택) / 심방유형(라디오)
- **동작**: `심방일지/{YYMMDD}_심방일지_{이름}.md` 생성 —
  - 프론트매터: 입력값 + `type: 심방일지` + 태그·world/route 자동
  - `📋 기본정보` 섹션을 **성도 노트 프론트매터에서 자동 채움** (성명·연락처·구역·직분·가족관계)
  - `📍 심방정보` 섹션도 모달 입력값으로 자동 채움
  - 나머지 5개 섹션은 빈 골격 + 안내 placeholder
  - 생성 후 노트를 열고 **커서를 `## 📝 대화내용` 아래에 위치** — 즉시 타이핑 시작
- **비용**: 클릭 2회 + 입력 2~3개 → 곧바로 본문 작성 (기존 수작업 10단계 → 1단계)

### 4.4 (d) 일지 → 성도 노트 반영 — 명시적 트리거 + 미리보기 (플러그인의 존재 이유)

**설계 결정**: 파일 저장 이벤트에 훅을 걸지 **않는다**. 일지는 여러 번 저장하며 쓰는 문서다. 저장마다 성도 노트를 건드리면 반쯤 쓴 요약이 박히거나 중복 반영된다. a4p 비파괴·dry-run 규율대로 **명시적 트리거 + 미리보기**로 간다.

- **진입점**: ① 일지 상단 배너 `↗ 성도 노트에 반영` (미반영 상태일 때만 표시) ② 커맨드 `성도: 심방일지 반영` ③ 대시보드 "미반영 일지" 목록
- **반영 모달 (미리보기 겸 확인)**:
  1. **요약 한 줄 자동 제안** — 대화내용 섹션의 볼드 주제 라벨을 추출해 `정기심방 (2026-03-08), 시니어 소그룹 후기, 박순옥 권사 무릎 수술` 형태로 제안 + **편집 가능한 입력칸**
  2. 성도 노트에 추가될 내용 미리보기: `## 📝 심방 기록`의 링크+요약 1줄, `## 📌 중요 심방 내용 (임베드)`의 `### 날짜 유형` 헤딩 + 임베드 3줄
  3. `심방상태: 필요 → 완료` 체크박스 (기본 켜짐)
  4. `[반영]` / `[취소]`
- **멱등성·안전성**:
  - 두 섹션을 헤딩 텍스트로 탐지, 섹션 **끝에 append만** — 기존 줄 무수정
  - 반영 완료 시 일지 프론트매터에 `반영: true` 기록 → 중복 반영 방지 + "미반영 일지" 검출 근거
  - 성도 노트에 해당 헤딩이 없으면 "섹션을 새로 만듭니다" 경고 후 문서 말미에 생성
  - 기존 항목보다 이른 날짜면 날짜순 삽입 위치 제안
- **비용**: 클릭 1회 → 요약 확인/수정 → 클릭 1회 (기존 수작업 ≈5분 → 10초)

### 4.5 (e) 후속조치 추적 — 패널 집계 + 원클릭 토글

- **데이터 소스**: 심방일지 폴더 전체의 `## 💡 후속조치` 섹션 체크박스 스캔. 별도 DB 없음 — `metadataCache` 이벤트로 메모리 캐시 갱신
- **UI**: 사이드 패널 후속조치 탭
  - 정렬: 일지 날짜 오래된 순 (묵은 약속부터)
  - 항목: `☐ 박순옥 권사 수술 전 심방 계획 — 홍길동 · 3/8 심방 · 34일 경과`
  - **패널에서 체크박스 직접 토글** → 해당 일지 파일의 해당 라인만 `- [ ]`→`- [x]` (명시적 클릭 = 승인, 단일 라인 변경)
  - 텍스트 클릭 → 일지 해당 라인으로 점프
  - 필터 칩: `전체 | 성도별 | 30일↑ 경과`
- **연쇄 효과**: 성도 노트의 `![[...#💡 후속조치]]` 임베드는 원본 라인이 바뀌므로 **자동 반영** — 추가 동기화 불필요

## 5. 사이드 패널(ItemView) 설계

**탭 3개**: `🏠 대시보드 | 👥 성도 | ✅ 후속조치` (브리핑은 성도 탭 안에서 전환)

### 5.1 대시보드 카드 우선순위

| 순위 | 카드 | 내용 · 근거 |
|------|------|-------------|
| 1 | ✅ **미완 후속조치** (상위 5 + 더보기) | 가장 actionable — "오늘 뭘 해야 하나"의 직접 답 |
| 2 | ❓ **심방 필요** | `심방상태: 필요` 성도. 각 항목에 `일지 작성` 바로가기 |
| 3 | ⏳ **장기 미심방** | 마지막 일지 기준 N개월 초과(설정, 기본 6개월). "완료"여도 오래됐으면 표시. `완료→필요 되돌리기` 제안 버튼 |
| 4 | 🎂 **생일** | 2주 내. 심방·연락의 자연스러운 계기 |
| 5 | 🌱 **새등록 성도** | 등록 90일 이내 + 심방 0건 — 새신자 정착 심방 누락 방지 |
| 6 | 📝 **미반영 일지** | `반영` 플래그 없는 일지 — 워크플로우 (d) 누락 회수 |
| 7 | 최근 심방 5건 (접힘) | 빠른 재열람 |

**의도적으로 뺀 것**: 출석점수·구역 통계 등 분석 지표 — `성도 관리.base` 9개 뷰가 담당. 카드 하단 `성도 관리.base 열기` 링크로 위임.

### 5.2 성도 탭

- 검색창(이름/구역/직분) + 목록: `이름 · 구역 · 심방상태 아이콘 · 마지막 심방 N개월 전`
- 항목 클릭 → 브리핑 뷰(v0.2), 아이콘: `📄 노트 열기` / `✍ 일지 작성`

## 6. 개인정보 보호

### 6.1 원칙

> **이 플러그인은 어떤 데이터도 외부로 전송하지 않는다.** 모든 처리는 로컬 볼트 파일 읽기·쓰기뿐이다. 요약 추출도 규칙 기반이며 AI API를 사용하지 않는다.

### 6.2 플러그인이 하는 것 3가지

| 기능 | 설명 | 원칙 |
|------|------|------|
| **동기화·git 노출 점검** | 설정 탭 버튼 — 성도 폴더가 ① git 추적 대상인지 ② 공유형 동기화 대상인지 검사 후 **경고만 표시**. `.gitignore` 추가 제안 문구 + 원클릭 복사 제공 | 자동 수정 안 함 — 사용자 설정 파일 불가침 |
| **화면 마스킹 토글** | 패널·브리핑·모달에서 연락처(`010-****-5678`)·생년월일 마스킹 (기본 켜짐, 상태바 아이콘) | **파일은 절대 변경하지 않고 표시 레이어만.** 용도: 화면 공유·프로젝션 노출 사고 방지 |
| **기록 최소화 안내** | 첫 성도 등록 시 온보딩 Notice 1회 — "심방에 필요한 최소 정보만 기록하세요 (주민번호·금융정보 기록 금지)" | 교육적 넛지 |

### 6.3 의도적으로 하지 않는 것 3가지 (근거)

| 배제 기능 | 근거 |
|-----------|------|
| **파일 암호화** | Obsidian 캐시·검색 인덱스·백업에 평문이 남아 반쪽짜리 보안. 허위 안전감이 더 위험. → 문서에 OS 차원 보호(FileVault, 암호화 디스크이미지) 안내로 대체 |
| **플러그인 접근 비밀번호** | 파일 직접 접근을 못 막으므로 허위 안전감만 제공 |
| **자동 파기/보존기한** | 삭제 자동화는 비파괴 원칙과 충돌. 필요 시 "N년 경과 일지 목록 조회"까지만 (확장 로드맵) |

## 7. MVP 범위와 로드맵

### v0.1 — 핵심 가치: "일지 하나 쓰면 나머지는 플러그인이"

1. 새 성도 등록 모달 (4.1)
2. 심방일지 생성 모달 + 파일명·프론트매터·기본정보 자동화 (4.3)
3. **일지 반영**: 링크+요약 제안+임베드+심방상태, 미리보기 모달 (4.4) — 존재 이유
4. 사이드 패널: 대시보드 + 후속조치 탭(토글 포함) (4.5, 5장)
5. 설정: 성도/일지 폴더 경로(기본값 포함) + **경로 검증 버튼**, 장기 미심방 기준 개월, 마스킹 기본값
6. 마스킹 토글 + 동기화 노출 점검 (6.2 — 구현비용 낮고 신뢰 확보에 중요)

### v0.2

- 심방 브리핑 탭 (4.2) — MVP에서는 성도 노트 자체가 브리핑 역할 임시 수행
- 성도 탭 검색 고도화, 주간 기도제목 모음, 기존 일지 소급 반영 마이그레이션(dry-run)

### v0.3+

- 월간 통계 리포트, 가족 단위 뷰, 봉사 필드 롤오버, 심방 일정, a4p-plaud 연계
- 상세: [03-확장아이디어.md](03-확장아이디어.md)

### 성공 기준

> 심방 1건 처리(일지 작성 → 성도 노트 반영 → 상태 갱신)가 수작업 대비 **클릭 5회 이내, 구조 관련 타이핑 0회**로 완료되고, 그 과정에서 **기존 노트의 어떤 줄도 수정·삭제되지 않는다.**
