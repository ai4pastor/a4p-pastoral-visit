## 2. 볼트 컨셉 확장 아이디어 (플러그인 밖, 강의 콘텐츠용)

현재 `460. 성도` 폴더 컨셉을 플러그인과 무관하게 확장할 수 있는 방향 — 강의에서 "옵시디언 목회 관리의 큰 그림"으로 제시할 재료:

1. **심방 → 목양 전반으로**: 심방일지 외에 `상담기록`·`전화심방`·`경조사` 타입 추가. 같은 파일명 규칙·반영 구조를 재사용하면 플러그인 확장도 자연스러움 (`visitTypes` 설정이 이미 커스터마이즈 가능)
2. **구역/목장 노트**: `type: 구역노트` — 구역 예배 기록, 구역원 목록은 Bases로 자동 집계. 구역장 리더십 케어 이력
3. **새신자 정착 파이프라인**: 등록 → 새신자반 → 세례 → 정착의 단계 필드 + 단계별 체크리스트. 대시보드 "새등록 성도" 카드의 자연스러운 확장
4. **연간 목양 리뷰**: 연말에 성도별 심방 횟수·기도제목 변화를 모아 "올해의 목양 회고" 노트 생성 — 통계 리포트(#4)의 목회적 버전
5. **사역자 인수인계 패키지**: 부임·이임 시 성도 폴더 전체가 곧 인수인계 문서가 되는 구조 — "노트가 단일 진실" 원칙의 실질적 열매로 강의에서 강조할 포인트

## 3. 강의 활용 시나리오

### 3.1 수강생 실습 세트

- 볼트의 **`469. 성도 실습(테스트)/` 폴더**(가명 성도 15명, 빈 템플릿 상태 — 2026-10-05에 `460. 성도/` 밖으로 이동)를 실습용 샘플 볼트로 재포장해 배포. 시연용 데이터(성도 53명·일지 28건)는 `scripts/demo-data/`가 재생성한다
- 실습 볼트 구성: 성도 노트 15개 + 빈 `심방일지/` 폴더 + `성도 관리.base` + 플러그인 사전 설치
- **모든 인명은 가명** — 실습 자료에 실제 교인 정보가 섞이지 않도록 배포 전 점검

### 3.2 실습 커리큘럼 (90분 기준 예시)

| 단계 | 내용 | 플러그인 기능 |
|------|------|---------------|
| 1 (15분) | 성도 노트 구조 이해 — 프론트매터가 곧 데이터베이스 | (배경 설명) |
| 2 (10분) | 새 성도 등록 실습 — 본인 교회 상황 가정 | 등록 모달 |
| 3 (20분) | 심방일지 작성 — 시나리오 카드(가상 심방 상황) 배부 | 일지 생성 모달 + 본문 작성 |
| 4 (15분) | 성도 노트 반영 — 미리보기에서 무엇이 자동화됐는지 확인 | 반영 모달 |
| 5 (10분) | 대시보드·후속조치 — "다음 주에 뭘 해야 하나" | 사이드 패널 |
| 6 (10분) | 개인정보 세션 — 마스킹·동기화 점검·기록 최소화 원칙 | 설정 탭 |
| 7 (10분) | Bases 뷰 연결 — 플러그인(할 일)과 Bases(분석)의 역할 분담 | 성도 관리.base |

### 3.3 강의 메시지 포인트

- **"플러그인을 지워도 볼트는 온전하다"** — 데이터 종속 없는 도구 선택의 기준 제시
- **"자동화는 목양을 대체하지 않고 목양의 시간을 돌려준다"** — 심방 1건당 5분의 구조 작업 → 10초
- **개인정보는 기술이 아니라 습관** — 마스킹·최소 기록·동기화 점검은 도구, 핵심은 목회자의 기록 윤리

## 4. 하지 않기로 한 것 (기록)

| 항목 | 이유 |
|------|------|
| 플러그인 전용 DB (SQLite 등) | 노트가 단일 진실. sermon-desk 수준의 복잡도는 심방 관리에 과잉 |
| 파일 암호화·접근 비밀번호 | 반쪽 보안 → 허위 안전감. OS 차원 보호 안내로 대체 (기획서 6.3) |
| 저장 시 자동 반영 훅 | 반쯤 쓴 일지가 성도 노트에 박히는 사고 방지. 명시적 트리거 유지 |
| 출석·통계 분석 뷰 | `성도 관리.base` 9개 뷰와 역할 중복 |
| 자동 파기/보존기한 | 삭제 자동화는 비파괴 원칙과 충돌 |
